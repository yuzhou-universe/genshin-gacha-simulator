# 原神风格抽卡模拟系统

FastAPI + SQLAlchemy 2.0（异步）+ DeepSeek Flash 实现的抽卡模拟器，含用户端与管理后台。

- **抽卡规则**对齐线上原神：角色池 0.6%／90 抽保底／74 抽起软保底／50-50 大保底；武器池 0.7%／80 抽保底／75% UP／神铸定轨；常驻池无 UP；新手池八折十连、限 20 抽。
- **规则全部存在数据库里**，管理员可在后台改概率、保底、UP 规则、定轨规则，改完立即生效，路由中没有任何魔法数字。
- **前端零依赖**：手写 CSS 与原生 JS，不引 CDN、不需要 npm、无构建步骤，**完全离线可用**。
- **AI 失败不影响抽卡**：这是拓扑上的保证，不是靠 try/except 兜出来的。

## 打包成软件（给不装 Python 的人用）

想把它交给别人用，不需要对方装 Python。跑一条命令：

```bash
.venv/Scripts/python.exe build_windows.py
```

产出在 `release/`：

| 文件 | 说明 |
|---|---|
| `原神抽卡模拟器-1.0.0-安装包.exe` | 安装向导：选目录、建开始菜单与桌面快捷方式、登记进「应用和功能」，**自带卸载程序** |
| `原神抽卡模拟器-1.0.0-便携版.zip` | 解压即用，不写注册表、不需要安装 |

前置：`pip install pyinstaller`；`winget install JRSoftware.InnoSetup --scope user`（用户级安装，不需要管理员）。

### 安装后是什么样

- 装到 `%LOCALAPPDATA%\Programs\原神抽卡模拟器\`，**全程不弹 UAC**
- 双击快捷方式 → 弹出启动器窗口（显示访问地址、管理员账号密码、数据目录），同时自动打开浏览器
- **首次运行生成随机管理员密码**并显示在启动器上。这一步是必要的：打包版没有源码目录的 `.env`，会回落到代码默认值 `Admin12345` —— 那等于每个拿到安装包的人都知道密码
- 数据存在 `%LOCALAPPDATA%\GenshinGacha\`（数据库、上传素材、运行时 `.env`）。**备份就复制这个目录**
- 卸载时询问是否删除用户数据，**默认保留**；静默卸载一律保留

### 两个设计要点

**只读资源与可写数据必须分开。** 装到 Program Files 之后程序目录不可写，所以模板与静态文件走 `RESOURCE_DIR`（PyInstaller 解包目录），数据库与上传走 `DATA_DIR`（用户目录）。详见 `app/core/paths.py`。

**首次运行必须先写 `.env` 再读配置。** 若路径解析住在 `config.py` 里，第一次 `import` 就会初始化 `Settings`，那时 `.env` 还不存在，配置会被永久冻结成默认值。所以启动器的顺序是 `paths` → `bootstrap`（写 .env）→ `app.main`。

### 已知限制

**安装包没有代码签名**（证书需要付费购买），所以 Windows SmartScreen 会提示「未知发布者」，需要点「更多信息」→「仍要运行」。便携版与安装包都一样。

## DeepSeek Flash 配置

在 `.env` 里填 `DEEPSEEK_API_KEY` 即可启用。四个用途：抽卡点评、卡池介绍、历史总结、角色台词。

```bash
DEEPSEEK_API_KEY=sk-你的密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_DISABLE_THINKING=true
```

**关于 `DEEPSEEK_DISABLE_THINKING`**：`deepseek-flash` 默认开启思考模式。生成"一句抽卡点评"这种短文本时，开启思考会把延迟和费用都消耗在思维链上，用户却只想要一句话。因此默认显式发送 `thinking: {"type": "disabled"}`。

**关于模型名**：`deepseek-flash` 是 DeepSeek 官方当前的模型 ID（V4.1-Flash）。旧的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 下线，不要用作兜底值。模型名传错时接口返回 **HTTP 400 `Model Not Exist`**（不是 404）。

### 降级行为

| 情况 | 表现 |
|---|---|
| 未配置密钥 | 不发任何网络请求，直接用本地模板 |
| 超时 / 连接失败 / 5xx / 429 | 指数退避 + 抖动重试（默认 2 次），仍失败则用本地模板 |
| 400 / 401 / 402 / 422 | **不重试**（重试不会变好），立即降级并进入 300 秒冷却，避免每次抽卡都白跑网络 |
| 200 但正文为空 | 视为失败并降级 |
| 卡池介绍 | 按卡池缓存 1 小时 |

**AI 永远不会阻塞或中断抽卡**：抽卡接口不调用 AI，点评由前端拿到结果后**另行**异步请求。所以无论模型出什么状况，抽卡结果都已经落库并完整呈现。

**隐私**：发送给模型的内容只有卡池名、物品名、星级、抽数、保底数。`comment_on_pull()` 的函数签名里根本没有 user 对象，调用方没有入口能把用户名、ID、密码哈希、会话或 IP 传出去。

## 抽卡规则

### 已实现的规则

| | 角色活动祈愿 | 武器活动祈愿 | 常驻祈愿 | 新手祈愿 |
|---|---|---|---|---|
| 五星基础概率 | 0.6% | 0.7% | 0.6% | 0.6% |
| 软保底 | 74 抽起 +6%/抽 | 63 抽起 +7%/抽 | 74 抽起 +6%/抽 | 同角色池 |
| 五星硬保底 | 90 抽 | 80 抽 | 90 抽 | 90 抽（20 抽上限下够不到） |
| 四星基础概率 | 5.1% | **6.0%** | 5.1% | 5.1% |
| 四星保底 | 10 抽 | 10 抽 | 10 抽 | 10 抽 |
| UP 规则 | 50% + 大保底 | 75%（两把各 37.5%）+ 大保底 | 无 UP | 无 UP |
| 定轨 | — | 命定值满 1 必出（可配置为 2） | — | — |
| 消耗 | 纠缠之缘 | 纠缠之缘 | 相遇之缘 | 相遇之缘（十连八折） |
| 抽取上限 | 不限 | 不限 | 不限 | 终身 20 抽 |

货币换算：**160 原石 = 1 纠缠之缘 = 1 相遇之缘**。道具不足时自动按此比例用原石补足。

### 两处与"常见写法"不同的地方

**1. 武器定轨的命定值上限默认是 1，不是 2。**
官方在 5.0（2024-08-28）把上限从 2 降为 1，最坏情况从 240 抽降到 160 抽。本项目默认对齐线上，但后台可改回 2（字段 `epitomized_max_points`）。

**2. 捕获明光（Capturing Radiance）默认关闭。**
这是 5.0 新增机制，会让角色池的实际 UP 率从 50% 升到约 55%，并在连续三次"歪后才中"之后强制下次不歪。后台可按卡池开启。

### 两条容易写错的状态机铁律

**① 出五星不重置四星计数器。**
`pity_4` 的语义是"距上一个**四星**的抽数"，不是"距上一个四星或以上"。出了五星只是"满足"了本抽的四星保底，该保底**顺延到下一抽**。把它重置成 0 会导致"出了金就吞掉一次四星保底"。

**② 定轨强制分支必须清掉大保底。**
结算顺序固定为：定轨强制 → 大保底 → 新鲜的 UP 判定。若定轨强制出金后不清掉大保底，那么"先在 75/25 上歪了（大保底置位，命定值 +1）→ 命定值满触发定轨强制"这条路径会留下陈旧的大保底，导致**再下一个五星又白送 UP**（双重白嫖）。

这两条都有专门的对抗性测试（`tests/test_gacha_engine.py`）。

### 其它已处理的坑

- **新手池使用独立保底组**，不与常驻池共用。否则八折的相遇之缘会免费推进常驻池的保底计数，是经济漏洞。
- **歪池按物品类型过滤**：角色池歪了只掉角色，武器池歪了只掉武器。
- **大保底跨卡池只搬"标志"不搬"物品"**，在新卡池按新卡池的 UP 集合结算。
- **命定值用惰性判定归零**（每次读取和抽卡时检查 `close_at`），不依赖定时任务——定时任务一旦失败，陈旧命定值会白送一把定轨武器。
- **`pity_4` 允许超过 10**：当四星保底那一抽被五星判定抢先命中时就会这样。因此比较一律用 `>=`，也不对存储值做 clamp。
- **武器池的软保底第 77 抽就到 100%**，硬保底 80 是失效参数。这不是 bug，后台界面会提示"本配置下保底在第 N 抽到达 100%"。

## 使用说明

### 用户端

- 注册（用户名 3-20 位，密码至少 8 位且含字母与数字）→ 登录后进入 `/gacha`
- 界面按**原神实机**布局：
  - **顶部**：卡池页签（带图标，可横向滚动）+ 原石（带「+」自助增加）+ 当前卡池消耗的那种缘
  - **中部**：整屏天空背景之上叠一张**居中横向海报卡** —— 左半幅是类型标签、卡池名、概率提升说明、「✦ 每十次祈愿必出四星或以上物品」高亮条、剩余时间倒计时（未设结束时间则显示「长期开放」）；右半幅是五星立绘、物品名牌与 UP! 角标。武器池额外在左半幅显示**神铸定轨的圆形命定值指示器**（如 `0/1`），点击可选择定轨武器
  - **底部**：另一种缘 + 「详情」（弹窗展示完整概率表与 UP 物品）+ 「历史记录」；右下是两枚大号祈愿按钮「祈愿1次 ✦×1」「祈愿10次 ✦×10」与 UID
  - 卡池主题色由类型派生（角色=青 / 武器=橙 / 常驻=紫），与实机一致，**不需要额外配置**
- **抽卡动画对所有卡池固定为同一套**（星光跃迁 → 逐个翻出 → 五星单独呈现），不随卡池切换而变化。演出本身保持**深色星空**（与实机一致），不跟着主界面的明亮风变亮
- 十连结果以网格展示；**五星最后单独呈现**，图片取该物品的 `image_url`，未设置时用内置占位图
- `/history`：分页、按卡池／星级／是否 UP／时间范围筛选、统计、CSV 导出（带 UTF-8 BOM，Excel 打开不乱码）
- 货币栏原石右侧有「+」，可自助增加 **10 / 160 / 1600** 原石（模拟器的便利功能，不是付费入口）

### 关于原石自助增加

档位与上限都可通过环境变量调整（`PRIMOGEM_TOPUP_OPTIONS` / `PRIMOGEM_TOPUP_CAP`，默认 10/160/1600、上限 500,000）。

两个实现上值得注意的点：

- **档位由服务端白名单校验**，客户端改不了。允许传任意数值等于开了个随便刷原石的口子，上限也就形同虚设（一次传 500000 即可）。
- **达到上限时是「截断」而不是「拒绝」**。若直接拒绝，余额停在 499,990 时任何档位都会超限，用户就永久卡死、再也加不了。截断后会如实告知本次实际加了多少。
- 余额**已经超过上限**时（例如管理员调低了上限）保持不变——"截断到上限"若写成无条件 `min(余额+增量, 上限)`，会在这里把 16000 直接调成 1000，加原石反而把原石扣走。
- 上限判定在**数据库层**用条件 `UPDATE` 完成，而不是"先读出来判断再写回去"——后者在并发下会双双通过检查，把余额顶到上限之上。

### 管理后台

用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录后自动跳转 `/admin`。普通用户访问任何 `/admin` 路径或后台 API 一律 **403**。

- **卡池管理**：增删改、启用/停用、开放/关闭、设为主推（全局唯一）、排序、开放时间
- **规则编辑**：概率、保底、软保底、UP 率、大保底、定轨、捕获明光
- **物品编辑**：名称、类型、星级、是否 UP、权重、展示图
- **素材管理**：上传全屏背景图／横幅／图标／五星展示图
- **全局配置**：新用户初始货币、抽卡动画参数、AI 提示词模板
- **操作日志**：记录每一次改动（谁、何时、改了什么、来源 IP），只记**变化的字段**

几条约定：

- 卡池的 `key` 与 `type` 创建后不可修改。前者是外部引用的稳定标识，后者会改变 UP/歪池的类型校验语义。
- **新建的卡池强制以停用状态创建**，物品没配全时不允许开放——避免出现"玩家看得见、点下去报错"的卡池。
- 规则改动**立即生效**：引擎每次抽卡都从数据库读，没有模块级缓存。
- 编辑卡池物品时按 id 差量更新，**不会清空玩家的定轨选择**。
- 删除卡池不会毁掉历史记录（记录里存有卡池名与物品名快照）。

## 技术选型说明

几个可能与你预期不同的选择，以及原因：

- **密码哈希用 `argon2-cffi` 而不是 `passlib`**：passlib 已停止维护，且在新版 Python 上会因标准库 `crypt` 模块被移除而导入失败。
- **认证用签名 Cookie 会话而不是 JWT**：服务端渲染 + 后台管理的场景下更简单也更安全（httpOnly、可即时登出、没有 token 泄露面）。
- **前端不引 Tailwind / Alpine / HTMX**：原神风格本身就是自定义的深蓝金色主题与星级光效，工具类帮助有限；不引 CDN 换来了完全离线可用与零构建。
- **统计 SQL 用 `CASE WHEN` 而不是 `iif`**：`iif` 是 SQLite 专有函数，PostgreSQL 上不存在。
- **所有规则列都带 `server_default`**：需求要求"规则放在数据库里"，那就应当由数据库自己兜底，而不是只靠 Python 侧默认值——否则任何绕过 ORM 的 INSERT 都会写进 NULL，随后概率计算会在 `None > x` 上抛 `TypeError`。
